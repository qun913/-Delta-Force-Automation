# delta-craft

《三角洲行动》手游 · 特勤处「收菜 + 下单」全自动。

跑在 [DSH Go](https://github.com/ccch1mneyyy/dsh-go) 的手机本机引擎上，用手机操控（无障碍）读屏、点按，不需要电脑参与，也不需要 root。

> 本项目只做特勤处制造。不做市场倒卖，不读写游戏数据，不注入进程。

## 它解决什么问题

特勤处一轮 8 小时。一天三次，每次你要：进游戏 → 关礼包弹窗 → 大厅 → 特勤处 → 三个台逐个看状态 → 收成品 → 选产物 → 数量拉满 → 缺料点一键补齐 → 下单 → 退出。

五六分钟纯重复。这个项目把它变成零操作——到点手机自己亮屏、自己跑完、自己熄灭。

## 它和市面上的脚本不一样在哪

现成的方案（如 [DeltaForceSS](https://github.com/yi-zelin/DeltaForceSS)、[DF-AutomatedTool](https://github.com/moligod/DF-AutomatedTool)）是**电脑端 + 坐标/模板 + OCR**：绑窗口、按固定坐标点、截图比对。好处是快，代价是每次赛季改版都要改配置文件重新对齐坐标。

这一套的流程是**写成自然语言状态表交给 agent**：它每次都是现场看截图判断「现在在哪一页、这个台在生产还是空闲、按钮是亮还是灰」，再决定下一步。界面改版不用改代码——这是它能长期免维护的原因，也是它比坐标宏慢的原因。

代价说清楚：慢（每步都要看一眼）、贵（要模型）、不保证 100% 准（认不出来就停，这是设计而不是缺陷）。

## ⚠️ 兼容性：先确认你的手机行不行

**这条链路依赖两个系统行为，部分机型做不到。做不到就只能半自动运行，不能全自动。**

### 条件 A：通知能点亮整屏

到点靠发一条通知把屏幕唤醒。但很多机型在「熄屏显示（AOD）」开启时，通知只点亮那一小块区域，屏幕并没有真正亮起来——任务照样无法执行。

**必须做的：**

- 设置 → 显示 → **关闭「熄屏显示 / 息屏显示」**
- 设置 → 通知 → DSH Go → 开启**「亮屏提醒 / 唤醒屏幕」**（不同品牌名称不同，有的叫「锁屏通知」「亮屏通知」）

**怎么判断行不行：** 锁屏状态下给手机发一条 DSH Go 的通知，观察屏幕是否整屏点亮。只亮一小块、或完全不亮，就是**不支持**。

### 条件 B：能关掉锁屏界面

DSH Go 的无障碍服务**碰不到锁屏界面**——读不到、点不到，连"上滑"都做不了。所以必须用 adb 把锁屏整个禁用。

```bash
adb shell locksettings get-disabled        # 先看当前值
adb shell locksettings set-disabled true   # 禁用锁屏，亮屏直接进桌面
adb shell locksettings set-disabled false  # 恢复
```

**怎么判断行不行：** 执行 `set-disabled true` 后**重启手机**，再执行 `get-disabled`。

- 返回 `true` → 支持
- 报 `SecurityException` / `Permission denied` / 需要 root → **不支持**（部分 ROM 限定了这个命令的调用者）
- 重启后变回 `false` → 部分支持，开机后需要重新执行一次

**这是全自动与半自动的分界线。** 做不到这一条的机器，只能走下面的降级方案。

### 条件 C：`tap_xy` 可用

需要在 DSH Go 的 `设置 › 手机操控` 里把确认方式改成「本任务免确认」或「始终免确认」，否则每一步都会弹确认卡，30 秒不选按拒绝处理，跑不完一轮。

### 降级方案（A 或 B 不满足时）

把确认方式保持「每次都询问」，定时任务触发后它发通知、你解锁、点确认，剩下的它自己做完。一天三次，每次十几秒。

## 前置条件

- 安卓手机一台（本项目在 vivo / OriginOS / Android 16 上验证）
- 安装 [DSH Go](https://github.com/ccch1mneyyy/dsh-go)，**在本机引擎上运行**（连接远程主机时手机操控不可用）
- 已配置支持图片输入的模型——三角洲是 Unity 自绘，无障碍树里 **0 个可读元素**，只能靠截图理解画面
- adb 可用（电脑上一次即可，用来执行条件 B 的命令）

手机侧还要配三项：

1. 设置 → 显示与亮度 → **休眠 → 10 分钟**（通知点亮后要撑住一整轮）
2. 设置 → 通知 → DSH Go → 允许通知 / 锁屏通知 / 亮屏提醒
3. 后台保活：电池不优化、允许自启动、最近任务里锁定 DSH Go

可选，但强烈建议：

```bash
# 授予「修改安全设置」，配合 DSH Go 的「自动恢复无障碍」，
# 防止系统杀掉无障碍服务后整轮失效
adb shell pm grant <DSH Go 的包名> android.permission.WRITE_SECURE_SETTINGS
```

包名用 `adb shell pm list packages | grep -i dsh` 查，不要照抄。

## 安装

把 `skills/delta-craft/` 整个目录放到手机的：

```
$DSH_HOME/skills/delta-craft/
```

`$DSH_HOME` 是 DSH Go 本机引擎的 home 目录（App 自带的那套 Linux 环境里）。目录里有 `SKILL.md` 就够了。

然后在 DSH Go 里建一个定时任务，每 30 分钟触发一次，任务内容：

> 按 delta-craft 技能执行。先做时间门控，不到点直接结束。

**为什么是每 30 分钟而不是精确到点：** 单次任务连续 3 分钟没操作会自动结束，挂不住长等待。所以用高频短任务 + 门控的方式：每次先算「现在离 `last_success + 8h` 还差多久」，没到点就直接退出，不读屏、不碰手机。这样"锁屏重试 30 分钟一次、最多 3 次"也顺带有了节拍。

## 全自动链路

```
到点（last_success + 8h）
  → 发通知（点亮屏幕）
  → 读屏：无锁屏，直接桌面
  → open com.tencent.tmgp.dfm
  → 关礼包弹窗（右上角 X）→ 大厅 → 特勤处
  → 三个台依次：有成品先收 → 选产物 → 数量拉满 → 一键补齐 → 下单
  → 每台存一张详情页截图
  → 回大厅 → 回桌面 → 屏幕按休眠时间自行熄灭
  → 更新 last_success（只在真的下了单时）
```

## 锚点式调度

8 小时是**产能时间**，不是钟点。固定 08:00 / 16:00 / 00:00 会越跑越偏：某天 08:40 才造上，16:00 到点时还没好，白跑一趟。

所以触发时间跟着「上一次成功下单的时刻」走：

1. `last_success` 只在**真下成单**后更新，失败一律不动——否则锚点会被越拖越歪
2. 触发时间 = `last_success + 8h`
3. 到点若屏幕没解锁：30 分钟后重试，最多 3 次；仍不行 → 放弃本轮并通知，等下一周期
4. 绝不硬闯锁屏、不尝试自行解锁

```json
{
  "capacity_hours": 8,
  "last_success": "2026-11-15T23:12:10+08:00",
  "next_target": "2026-11-16T07:12:10+08:00",
  "cycle_attempts": 0,
  "give_up_until": null
}
```

首次的 `last_success` 可以由界面上的倒计时反推（三台都显示 07:12 出料，减 8 小时 = 23:12），此后由真实下单时刻覆盖。

## 状态表（SKILL.md 节选）

每次操作后重新截图判断当前状态，认不出来就停，不盲点。

| 状态 | 识别特征 | 动作 |
|---|---|---|
| 启动/过场 | 厂商 logo、公告、点击进入 | 能点的点掉；不认识就停 |
| 登录页 | 账号密码框、验证码 | **停**，交还用户 |
| 大厅 | 底部：仓库 / 部门 / 交易行 / 特战干员 / 特勤处 / 改枪台 | 点「特勤处」 |
| 特勤处主页 | 左上标题「特勤处」 | 逐台处理 |
| 某台·生产中 | 卡片上有物品图标和倒计时 | 跳过 |
| 某台·有成品 | 卡片有「!」或可收取标识 | 先收再下单 |
| 某台·空闲 | 卡片显示「空闲中 / ＋」 | 进去下单 |
| 详情页·材料不足 | 「制造」灰、有「一键补齐」 | 点补齐，买完回详情页 |
| 详情页·材料够 | 「制造」是亮的 | 点制造 |

完整版在 [`skills/delta-craft/SKILL.md`](skills/delta-craft/SKILL.md)。

## 实测踩到的坑

都是真机跑出来的，文档里没写：

- 三角洲无障碍树里 **0 个可读元素**。别指望"读控件文字"，只能靠截图看像素
- `tap_xy` 默认每次都要用户确认
- 锁屏界面是**无障碍禁区**：读不到、点不到，上滑也不行
- 熄屏会**直接终止**任务
- 连续 3 分钟无操作，任务自动结束
- 每次进游戏都有礼包广告弹窗。**只点右上角 X，绝不点「前往获取」**
- 「取消密码」≠「取消锁屏」。vivo 上只有两档：有密码 → 亮屏后输密码；无密码 → 亮屏后上滑。两档都挡路，所以必须靠 adb 关掉 Keyguard
- 关掉熄屏显示 + 开启亮屏提醒之后，通知才能把整屏点亮。之前只亮 AOD 那一小块

## ⚠️ 安全代价

**关掉锁屏意味着手机丢失即完全暴露。**

- 建议给支付、银行、微信等 App **单独开应用锁**
- 不要在这台机器上存证件照、支付密码
- 绝不让 AI 接触支付密码——本项目全程不输入任何密码，遇到密码框直接停
- 只想临时试的话，用完执行 `adb shell locksettings set-disabled false` 恢复

## 已知限制

- 不做无人值守承诺：**条件 A / B 不满足的机型，全自动不成立**
- 关锁屏在部分 ROM 上重启后失效，或被安全策略重置，需要复查
- 只支持 16:9 以外的分辨率要靠模型自己适应，没有做坐标适配
- 界面概率性出现登录页时，会停下并交还用户，不会尝试输入
- 材料不足依赖游戏的「一键补齐」；买不到或有异常页面时停止并报告
